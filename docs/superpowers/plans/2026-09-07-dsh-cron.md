# DSH Cron Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and package an independent `dsh-cron` plugin that runs persistent Workspace-bound Cron tasks in fixed or fresh Sessions, exposes controlled model tools, and provides an expandable in-conversation manager with execution history.

**Architecture:** The Host stores definitions, runtime checkpoints, pending occurrences, and execution history in a plugin-owned storage domain. `node-cron` exclusively owns expression validation, timezone/DST behavior, next-run calculation, and live timers; plugin services own Workspace authorization, Session dispatch, recovery, and single-flight/coalescing. The Client uses only the official keyed `tool.call.toolview` seam: `cron_open_manager` first renders a suggestion card and expands that same conversation row only after a user gesture.

**Tech Stack:** Node.js 24, TypeScript 6, `node-cron` 4.x, Zod 4, Cordis Host/Client plugins, DSH storage domains, SessionController, Agent and permission presets, Typert Remote, React 19, Vitest, jsdom, pnpm 11.

## Global Constraints

- Keep all Cron business code in `plugins/cron`; never modify, fork, patch,
  publish, or write through `deepseek-harness-source`, `upstream`, or any other
  DeepSeek Harness checkout. Do not update `upstream.lock.json` for this feature.
- DSH process lifetime is the only scheduler lifetime; no offline daemon, operating-system service, or Tauri scheduling code.
- Accept POSIX-style five-field Cron only: wildcard, list, range, and step; day-of-month/day-of-week OR semantics; no seconds, Quartz, or macros.
- Use explicit IANA timezone per Cron; creation defaults to the browser timezone and later system changes do not rewrite it.
- Bind every definition permanently to the current Workspace resolved by the Host.
- Support `existing_session` and `new_session`; fresh Sessions use the captured Agent preset and permission preset `workspace-write` (sandbox `workspace-write`, approval `ask`).
- Never inherit `danger-full-access` or approval policy `never` into a fresh execution Session.
- Keep at most one active execution and one latest pending occurrence per Cron.
- Startup produces at most one delayed catch-up per active Cron and never enumerates a backlog.
- Pause and delete clear pending work but never cancel an active or approval-blocked Session Run.
- Delete is terminal and retains definition and history; no restore operation exists.
- Keep all history in version 1; add cursor pagination but no retention or cleanup.
- Model create, update, delete, and resume require per-operation confirmation; model pause does not. Explicit manager clicks are direct gestures and receive no second approval.
- Foreign and unknown IDs have the same minimal failure. No fallback Workspace, Session, preset, timezone, or permission is guessed.
- Do not migrate, alias, or change `@deepseek-ai/dsh-schedule`.

```ts
import cron, { type ScheduledTask, type TaskContext } from 'node-cron'

export class CronLibrary {
  validate(rule: CronRule): CronValidation {
    if (rule.expression.trim().split(/\s+/u).length !== 5 || rule.expression.startsWith('@')) {
      return { ok: false, code: 'invalid_expression' }
    }
    try {
      if (!cron.validate(rule.expression)) return { ok: false, code: 'invalid_expression' }
      const probe = cron.createTask(rule.expression, () => {}, { timezone: rule.timezone })
      probe.destroy()
      return { ok: true }
    } catch {
      return { ok: false, code: 'invalid_timezone' }
    }
  }

    const task = cron.createTask(definition.expression, async (context: TaskContext) => {
      await onOccurrence(context.date)
    }, { name: definition.id, timezone: definition.timezone })
    task.start()
    return liveTask(task)
  }
}
```

- [x] **Step 4: Implement and test browser timezone extraction**

`timezoneForOpenTurn()` receives the invoking Agent Session events, finds the

```ts
export function timezoneForOpenTurn(events: readonly SessionEvent[]): string {
  const openTurn = events.slice(lastTerminalTurnBoundary(events) + 1)
  const zones = openTurn
    .filter(isOrdinaryUserRpcMessage)
    .map(event => canonicalTimeZone(event.clientTimeZone))
    .filter((zone): zone is string => zone !== undefined)
  const unique = new Set(zones)
  if (unique.size !== 1) throw cronFailure('invalid_timezone')
  return zones[0]!
}
```

```ts
private enqueue(id: CronId, operation: () => Promise<void>): Promise<void> {
  const prior = this.tails.get(id) ?? Promise.resolve()
  const next = prior.then(operation, operation)
  this.tails.set(id, next.finally(() => {
    if (this.tails.get(id) === next) this.tails.delete(id)
  }))
  return next
}
```
