# WeCom Session Workspace Template Design

## Goal

Give every newly created WeCom-backed Harness session a valid working directory so agent prompt assembly can resolve `{{cwd}}` and produce a reply.

## Configuration

The WeCom plugin adds `sessionWorkspaceTemplate`. Its default is the operating system temporary directory followed by `deepseek-harness-wecom/{{session}}`.

The configured value must resolve to an absolute path. Every occurrence of `{{session}}` is replaced with the Harness session ID. If the template contains no `{{session}}` token, all newly created WeCom sessions use the same configured directory.

The Plugin configuration card describes this setting in Chinese and English.

## Runtime behavior

Before creating a new Harness agent, the plugin resolves the workspace template for that session, recursively creates the directory, and writes the resolved path to the durable session `meta.cwd`.

Existing room mappings and existing sessions whose metadata lacks `cwd` are left unchanged. They are not migrated or replaced.

## Errors and safety

Invalid non-absolute configuration prevents the plugin from applying. Directory creation failure rejects that inbound turn and does not create a partially configured agent session. Session IDs are generated by Harness and inserted only as one path component value supplied by the plugin.

## Verification

Tests cover the default template, a custom template with `{{session}}`, a shared template without the token, recursive directory creation, and directory-creation failure. The complete WeCom suite, build, package, real profile installation, Gateway status, inbound Session creation, agent response, and referenced WeCom reply form the release checks.
